# Phase 12 local verification evidence

Executed on 2026-09-28/29 with synthetic records only: Next.js on localhost, Spring Boot 4.1.1 and Java 21, PostgreSQL 18 in an isolated WSL database, and a local Hardhat chain (chain ID 31337). No production credentials, personal recipient data, or Sepolia transactions were used. The browser issue and revoke actions were performed through the portal; the public result pages were captured with headless Chrome.

- Unknown ID `CERT-2026-999999` returned the same not-found view used for unpublished certificates: [not found](phase12-not-found.png).
- Issuing `CERT-2026-000003` from a draft produced a confirmed local-chain transaction and a matching public proof: [valid](phase12-valid.png). Its PDF artifact was generated. A separate local-chain integration test confirmed that a second issue request returns the existing transaction instead of submitting another one.
- `CERT-2026-000004` had issue and expiry dates of 2026-09-28. It verified as `VALID` on that UTC date. A test-classpath-only Clock advanced the read date by one day; verification then returned `EXPIRED` while the proof still matched: [expired](phase12-expired.png).
- `CERT-2026-000001` was issued and then revoked through the portal confirmation with a synthetic private reason. Reverification returned `REVOKED` with a matching proof; the public view did not reveal the reason: [revoked](phase12-revoked.png).
- For `CERT-2026-000003`, changing one synthetic database program name after issuance returned `PROOF_MISMATCH`, `blockchainVerified=false`, and no valid status: [proof mismatch](phase12-proof-mismatch.png). Restoring the field returned `VERIFIED` and `VALID` again.

Backend `./mvnw test` passed with 67 tests reported: 29 executed and 38 Docker-backed Testcontainers tests skipped. The opt-in external PostgreSQL suite executed 5 tests with no skips or failures, including a second run against a newly created empty database. Flyway applied V1 through V4 there, and Hibernate `ddl-auto: validate` started successfully. The opt-in external local-chain suite executed 3 tests with no skips or failures. Frontend lint, production build, and 28 component/service tests passed. Contract TypeScript check, 8 tests, and coverage passed; `CertificateRegistry.sol` had full line and statement coverage.

The security review checked that protected routes derive tenant identity from the authenticated principal; a real PostgreSQL HTTP integration test covers cross-tenant certificate read, edit, issue, reconcile, revoke, PDF, and email routes. Other checks covered JWT/cookie settings, CSRF, CORS, BCrypt, validation, public error disclosure, private storage paths, logo handling, explorer URL construction, RPC/network and receipt validation, contract roles, and private-key isolation. A scan of tracked Git history found no high-confidence secret patterns. Frontend npm audit had no advisories; blockchain npm audit reported 11 low-severity transitive development-tool advisories. An OSV query of 203 resolved production Maven packages found no advisories after updating Tomcat, Bouncy Castle, and Vert.x dependencies. OWASP Dependency-Check could not refresh its NVD database without an API key.

Docker Desktop repeatedly failed before its engine started with Windows socket rename errors for `sailor-ingest.sock` and `docker-secrets-engine/engine.sock` (Windows error 1920), including after factory reset. The Testcontainers classes and a full PostgreSQL-backed Mailpit smoke test therefore remain unverified on this machine. The public verification rate limiter is in process memory, so a multi-instance deployment needs a shared limit store. Production deployment, Sepolia, backup/restore, and production secret handling remain outside this local verification.
